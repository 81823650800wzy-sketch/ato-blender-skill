# 手机控件进入现实：臆想 vlog 制作案例

## 状态与适用范围

2026-10-16，用户在多轮修订后明确反馈：“记录本次制作，更新skill，这次做的不错”。本例可作为**用户认可的整体制作案例**，用于手机界面进入实景、控件驱动换景与现实反差收尾。认可不表示每个历史版本均通过，也不代替听检或逐帧审查。

本记录依据已保存的制作对话和历史交付报告整理。更新技能时 `<本机案例库>` 不可访问，未重新打开成片、检查媒体或执行项目脚本。下文数字是历史记录，使用原工程前应重新核对。技能仅保存方法和入口，不附带用户媒体、音乐、字体或个人聊天截图。

## 叙事链与用户选择

1. 实拍手机的上滑手势触发控制中心组件；全部组件分别弹出，再进入有重量的下落，与拍摄场景交互。
2. 镜头聚焦工作组件，切为勿扰；原本静音的音量缓慢上拉至满，BGM 随之渐入。随后开启飞行模式，飞机图标沿原朝向放大滑翔，衔接同向真实飞机镜头。
3. 亮度、护眼、省电、视效增强、清除桌面五组控件依次驱动风景。亮度滑动对应明暗；护眼对应绿植；省电对应乡村生活；视效增强对应色调；清除桌面对应干净城市。每组至少五个不同来源素材，共至少二十五段；这不是全部控制中心组件各配五段。
4. 接近录制结束时，小尺寸微信通知从上方进入，背景视频继续播放；画面逐渐变灰，音乐变得沙哑，通知摇晃、坠落、破碎，随后点击录屏键结束录制。
5. 经退出转场切回另一段手机实拍。手机平面上悬浮余额界面，随真实摇晃与银币落下，钱包图标和余额字形一起散落；镜头靠近散落余额，延续变调、降音量的音乐，缓慢结束。

这些是本片的创作选择，不是新任务的必选清单。后续只改局部时保留用户认可的段落、素材顺序与时间线，避免无关重做。

## 有效实现与修订教训

| 用户修正或失败现象 | 可迁移的方法 | 检查重点 |
|---|---|---|
| 组件出现早于上滑，画面不连贯 | 从连续实拍帧定位手指上划和导航栏响应，再安排首个组件的可见帧 | 区分源时间码、工程时间、首个实际可见像素；不能只看动画名义起点 |
| 要全部组件各自弹出 | 为每个组件保留身份、独立出现、状态和运动轨迹；聚焦段可一次展示一个主控件 | 不把组合大贴图当作独立组件；不漏掉初始组件 |
| 磨砂玻璃与手机内效果不一致 | 玻璃底、圆角边缘、图标、文本、滑块填充和状态色分层；以可靠截图校正图标 | 在最终背景上比较透光、模糊、圆角和高光，避免只在灰底验收 |
| 物理太轻、与实景穿模 | 加强释放速度、重力和落地阻尼；为桌面、手机、键盘及可见障碍建立对应接触/遮挡关系 | 屏幕边框碰撞不等于场景碰撞；动画曲线、求解器和遮挡分别验证 |
| 风景单调、看不出控件在控制 | 控件状态变化先建立因果，再以不同运动方向、景别、区域蒙版和明暗关系揭示新素材 | 新蒙版不等于新素材；核查来源身份与各组数量，不能用随机切镜替代因果 |
| 飞机转场缺乏连续性 | 使用原组件飞机图标方向，匹配实拍飞机的滑翔方向与画面运动 | 图标轮廓、扩张方向、接力端点与镜头朝向一致 |
| 通知过大、背景停住 | 缩小通知并维持阅读窗口；底片按源时钟持续播放，通知单独合成 | 通知、灰化、破碎不可意外将底片替换成冻结帧 |
| 完整通知与碎片重复出现 | 整体、应力摇晃、破碎状态只有一个可见所有者；碎片共享原通知 UV | 图标、头像、文字与玻璃同源切分；禁止文字悬空或破碎后完整副本残留 |
| 余额落在遮挡物后，看不见结果 | 调整合理的初速度和落点，把字形落在可见桌面区域 | 不为露出字形删掉真实前景遮罩；接触阴影与背景/前景同一时间 |
| 录制结束导致音乐中断 | 把录制停止作为视觉事件，按明确要求继续同一音乐，单独渐变音高、音量和音色 | 变调与变速分开；不要把降半音表述为已改成小调 |
| 文件前段低噪声被误当提示音起音 | 波形/RMS 找有效瞬态，保留短攻击前沿，再对齐首个真正可见帧 | 静音裁切阈值需要适应当前素材；不能按文件头或固定绝对阈值决定听觉落点 |

## 追踪、物理与遮挡的分工

手机与桌面使用独立平面追踪。手机上的余额挂载跟随手机单应，释放后进入坠落轨迹，落地后跟随桌面单应。任何时间重映射必须共享一个源时钟：底片、追踪矩阵、前景遮挡、真实银币、合成物体和接触阴影都从同一源时刻取样。

保真实拍时，生成图片只提供辅助 alpha 先验；与源帧配准、精修，再动态传播，前景 RGB 仍取原视频。手、袖口、手机、线缆、背带、耳机盒和实拍银币按实际前后关系遮挡合成物体，调色放在合成之后统一处理。

钱包图标和 `¥ 2 . 0 0` 是独立对象。释放时移交可见性，原卡片余额退出，不能同时显示原数字与掉落数字。字形透明留白框重叠与实际不透明字形相交分别统计，接触面高度、桌边越界和前景遮挡也分别检查。

本例有投影高度的 2.5D 动力学和经验证的平面追踪；不能宣称已完成度量级三维场景重建、所有刚体相互碰撞或全空间绝对零穿模。追踪误差较低仍需看弱纹理/遮挡区连续帧；跟踪失效时重新锚定、缩短有效区间或修正方案。

收尾先让物体落稳，再平滑推进与聚焦；用连续实拍慢放、克制的冷灰色、暗角和逐层减弱的亮度收束。背景不能因追焦而意外冻结，数字不能为营造情绪在地面滑移。最后淡出作用于真正结尾，而不是录制停止处。

## 提示音与音乐的关键修正

网络样本标为微信提示音并不能证明符合用户所指版本。用户提供指定文件后，用该文件替换旧提示音，保留来源说明，不叠加两个提示音。短提示音检测规则不能推广为自动删掉对白、音乐中的低声段。

本例 V9 以绝对幅值阈值 `0.0005` 检出约 `0.1524s` 的前导噪声；真实提示音尚未开始，导致可听事件仍晚到。V10 改为 2ms RMS 窗，结合噪声基线和峰值阈值定位有效起音：候选阈值为 `max(0.002, peak × 0.008, leading_noise_RMS × 12)`。这是本文件的参数，不是通用标准。

最终检测起音 `0.8864167s`，裁切点 `0.8844167s`，保留约 2ms 攻击前沿；通知首个可见帧为零基帧 1484，即 `29.68s`。音频放在该位置，有效 RMS 起音约 `29.682s`。名义动画起点 `29.64s` 时通知仍在画外，不能拿它做声音对齐依据。该约 2ms 差值是数值检查，不冒称人工听检通过。

音乐、保留音效、通知独立分轨，避免在未知混音上盲目相减。若确有旧 cue 的精确波形、增益与量化信息，修复后检查其影响区间及区间外样本；重新编码 AAC 后还要检查编码时延，不将母带样本相同写成压缩音轨字节相同。

用户明确要求录制结束后音乐继续。本例以保持速度的音高滑变、较低音量、柔化高频和轻混响形成低落尾奏；它没有生成新歌曲，也没有证明和声已从大调改成小调。
