# 三输入开工与完整工程

| 用户输入 | 可接受形式 | agent负责 |
|---|---|---|
| 歌曲 | 音频文件、已有工程音轨 | 探测、保留源音频、分析情绪与段落、定位时间候选 |
| 素材 | 视频、图片、文件夹、明确的检索要求 | 探测、接触表、选镜、角色/空间归类、来源建档 |
| 剪辑方式/意图 | 高燃混剪、vlog、叙事、海报、参考，或“你自主判断” | 按内容判断段落风格，转成镜头行为，逐镜分配二维/Blender |

已有会话信息足够时不重新索要。参考、原片、生成素材与成片分别记录角色；“参考它”不等于“剪进成片”。用户要求自行搜索时，选择可下载且许可明确的来源，记录署名、链接、实际规格、许可范围与改编行为。画面和录音授权分别记录，用户歌曲不自动成为可公开再分发音乐。

## 缺省与继承

- 完整MV用完整歌曲；明确秒数的混剪才裁歌。范围确实无法判断时只问范围，继续独立媒体分析。
- 普通横屏1920×1080，明显竖屏意图1080×1920，缺省30fps；已认可规格与用户选择优先。60fps须有足够源时间采样或明确插帧，重复帧不称原生60fps。
- 海报/平面按最大投影准备，争取约1.25倍像素余量；先查看实际生成尺寸，不因提示词“4K”宣称4K。动作混剪尽量用连续视频。
- 镜头数按音乐、动作和素材质量分配，不套历史数量/比例。高燃允许蓄力、静止反差与高潮后收束。
- 保存新版本，不覆盖既有交付。目录不可靠读写时验证工作副本，转到可用目录继续并报告；不自行修复文件系统或迁移/删除原库。

## 工程数据

建议 `sources / assets/generated / assets/layers / analysis / scenes / renders / delivery / reviews`。

`project.json`保留三输入、原请求、duration/fps/width/height、音频入点、输出根目录、素材角色、来源、镜头时间线和检查状态。`timeline.json`逐镜记录源与入点、输出起止帧、动作峰值、音乐事件、所选手法、图层、转场端点、文字范围和审查时点。按整数输出帧组织，音频采样不强制裁到同一帧格。

开工时直接探测实际输入并写入这两份记录；不要假定存在通用的一键成片脚本。按当前路线改写案例构建器或生成新的剪辑脚本，将硬编码路径、旧音频与旧时间线替换为本项目配置。二维极繁路线可使用已安装 `maximalist-animation` 的实际 `workflow.py init/analyze/validate/preview/render/review` 入口；先读它的项目 schema 再填充，不能把此处建议字段直接传给另一引擎。

用户只需这样调用：

> $ato-blender 歌曲：song.mp3；素材：素材文件夹；剪辑方式：高燃混剪，高潮加入生图海报、撕纸分层和左右空间运镜。

agent 开始后依次完成媒体接触表和音源探测、音乐段落/动作落点、逐镜计划、实际素材生成与分层、代表连续短段、完整时间线、成片与工程审查。代表短段是内部质量检查，不是需要用户另发“继续”才渲染全片的停点。素材少时先复用不同源区间/景别、补充适合该风格的生成画面；若不能满足用户要求的真实动作，说明具体缺口，不用静帧摆动伪装。

未指定目标时长时采用完整歌曲；用户只说“短视频/短混剪”且未给秒数，可暂定约30秒、按完整乐句微调并告知。指定参考的时长/画幅可合理继承，明确要求优先。缺少必要歌曲文件、不可读取的素材或方向彼此冲突才需要追问。

后续替换音乐/素材只调整必要数据和镜头；保留用户当前方向。
