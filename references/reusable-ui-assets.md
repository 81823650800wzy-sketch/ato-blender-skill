# 常用组件与剪辑资产库

适用于反复出现在 vlog 中的生活常见组件：手机控制中心、播放器、通知、相机、音量/亮度、导航等。它们应具有真实熟悉的内部结构、可辨认状态及有意义的交互。用户已选择默认建库：此类组件优先查资产库，缺失时制作 Blender 资产并登记，以便当前剪辑和后续复用；一次性装饰不强制建库。

## 来源与两次提取

- 从官方截图、真实录屏或许可可用图片确定具体版本、图标形状、比例、文字和状态。蜂窝网络、热点、AirDrop、蓝牙等不能凭大意混画；没有可靠截图时继续查找。
- 实际调用生图模型提取透明组件或还原缺失背景；保留原图、完整提示词、生成结果、实际尺寸和 alpha。再对照原图做第二次抠边、孔洞/细线检查和图标纠偏。原始截图的准确图标像素可作为最终纹理，不把模型近似图标当真实标志。
- 按组件拆成背景玻璃、图标/文字、填充、状态和遮挡层。图层设计可由生图分别生成前景、中景、远景，按深度错时进入；清除旧主体残影并补全移开后露出的背景。保真实拍和明确允许的生成重构分别标注。

## Blender 原生资产

- 用真实相机和组件局部坐标制作透视；圆角壳体、厚度/倒角、图标纹理、填充和交互 rig 保持独立。不能只把已合成 MP4 放进 Blender 后称其为组件资产。
- 先对照教程/参考的落位、倾斜、遮挡与共同运动。存在可靠实景参照物时按其空间关系确定透视；无可靠参照物的悬浮组件，默认以画面的视觉中心作为相机主点与空间运动/旋转的基准，缺省为画幅中心。记录实际中心坐标，避免随意偏移相机或各组件各自建立不一致的空间基准。视觉中心是构图与相机的基准，不表示所有不同方向的边线都必须汇聚在一个消失点；斜向消失点仍由真实三维几何决定。教程中接近正面的组件不得为了“有三维感”额外加大侧倾。
- 常用参数包括尺度、圆角、厚度、IOR、粗糙度、玻璃着色、图标对比度、活动状态及按压/展开进度。保持图片纵横比，禁止为适应布局任意拉伸符号。
- Collection/对象标记为 Asset，保留局部原点、挂载点、名称、版本、可编辑动作和元数据。资产预览需要能看到真实材质和关键图标；动画资产附短 MP4，不能只交付未渲染 `.blend`。
- 建库位置从当前工作区或已有资产索引发现，记录健康可读的路径，不硬编码他人私有目录。索引保存类型、来源/许可、Blender 版本、依赖、参数、动作、预览和验证状态；项目使用相对路径或打包依赖。项目数据与可分发 skill 指令分离，skill 不携带私片或私有工程绝对路径。

## 液态玻璃参考

以 Apple 官方资料核对目标材质。关注透镜式折射、圆润边缘和随角度/光源变化的高光、内容透过与适度模糊、可读性的背景适应，以及按压时局部形变/亮起和展开时的连贯过渡。不要把同一种强折射与模糊套在所有小图标上。

在 Blender 用可编辑几何与材质、灯光、相机、背景实现这些可见行为。EEVEE 的 raytraced transmission 或 Cycles 按实际版本验证，不能从材质参数存在就宣称折射已生效。软件实现仅称 Liquid Glass 风格参考，不冒充 Apple 私有渲染算法或原生系统组件；图标版本与材质风格版本分别记录。

## 使用与验证

### 场景中的低反光与轻磨砂

默认让组件融入当前场景的光，而非继承产品展示台的强软箱反光。按背景明暗、光源方位与冷暖选择宽柔环境光；换景时相应调整。以轻微磨砂、较低镜面/涂层响应及适当 IOR 减少刺眼高光，保持图标和文字清晰，避免大片白反射遮住信息。粗糙度等数值按实际材质、曝光、背景和角度检查，不把一次项目的固定参数当普遍标准。透过玻璃的白色背景内容与自身反光需要区分，不能通过压黑整个组件掩盖问题。

### 构图、连续性与屏幕容器物理

- 先观察当前素材的主体位置、动作区域、左右空白和视觉重量，再决定每个组件的落位、尺寸与倾角。视觉中心是相机/空间基准，不是组件必须集中摆放的位置。没有参照物也应按构图分布，避免一侧堆满而另一侧无意空缺；留白只有承担阅读、动作或节奏用途时才保留。
- 学习参考的因果与制作思路，不机械复制组件数量或位置。建立跨镜头的组件身份表：上一场景出现的对象应在下一场景有可见承接；参考只有四个，不代表当前已有更多组件时应删至四个。有意减少必须有当前叙事依据和清楚的退出动作，不把删掉多余对象当作连续性。
- 连续性锚点不仅保留数量/身份，也保留已确立的布局。用户要求原位下落时，组件不用重新分散、转移到新位置或再缩放，直接从原位交给物理求解；若主体被堆叠遮挡，先调整底景构图。用 [ODD 错层接力](edit-language.md#odd-错层接力与局部提速) 让下一画面内容在上一层未结束时预备进入，保留层次与错落，别把一串动画顺次等待播放。
- 采用下落结尾时，先按当前画幅把屏幕四边作为真实碰撞容器：边界应在相机投影中与画面吻合，透视相机需考虑深度/厚度，不能用更大的离屏盒子。保持组件整体、图标、玻璃与状态层一起运动；重力、质量、摩擦、回弹和碰撞推动运动，允许有原因的转动、回弹、堆叠，不用向外飞走或透明消失代替受容器限制的下落。
- 对屏幕平面的组件可约束为平面内运动与旋转，避免向相机/背景逃逸。碰撞代理按实际可见轮廓和尺寸制作，帧率、单位、子步数和求解精度随尺寸/速度选择。检查整个下落过程、所有对象的画面边界和堆叠，不只看落地的单帧。碰撞声音从实际接触/速度变化中安排，去掉已无对应动作的散开 whoosh。
- 保留可重算的原生物理工程和参数；另将已验证的求解结果烘成可移植关键帧用于渲染。资产库记录材料、身份承接、屏幕边界和物理参数的使用方法，便于不同画幅、素材和对象数量中重新计算；不把当前构图或某次碰撞结果强制套给下一条视频。

入场/落位/退出和点击/滑动是不同事件。音效对应真实状态变化、运动速度峰值或接触帧，声音分轨保留；无关镜头不机械套用同一 whoosh。实景挂载另做追踪/遮挡验证；生成分层场景可使用主动设计的空间相机，不能混称真实相机解算。

### 聊天组件的叙事与出现条件

有色玻璃聊天的材质、原位释放、源UV统一破碎、声音及已修复的速度交接陷阱见 [聊天玻璃坠落破碎](chat-glass-drop-shatter.md)。遇到类似需求先查已有静态资产、动作参考与配方，再按当前镜头重新求解。

- 用参考界面确定圆角、尾部、头像、字体和发送/接收关系；私人聊天截图只作样式时，另写原创文案与头像。个性化艺术字保持可读，玻璃着色与半透明不能盖掉关键实景主体。常用聊天框也做成独立 Blender 资产，保留壳体、文字、头像与参数。
- 出现条件由当前用户决定。用户限定“只有素材主体为手机时出现”时，先建立手机主镜头的可见窗口，再安排整个入场、阅读、坠落、破碎和淡出；碎片也须在纯风景成为主体前退出。城市风景的情绪留白不自动叠聊天。不要将这个项目的限定强制套给所有以后的视频。
- 对话有主线与清楚的发送者身份，回到宿舍等本人行为由本人气泡承接；调整时间线后检查头像、颜色、文案和阅读窗口，不只改气泡的开始时间。
- 破碎资产按同一源 UV 分割玻璃、字形和头像，并由同一碎片根对象运动、淡出，避免玻璃破碎而整行文字悬空。保留真实物理缓存及其求解范围；独立求解的波次不能宣称已经验证彼此碰撞。音效对齐新的接触和破碎帧。
- 实拍手机/手部前景可用两次生图抠像作 alpha 参考，配准后以源视频 RGB 合成；动态传播另检边缘、孔洞、手指和手机圆角。生成 RGB 不能替换保真实拍而不说明。必要时柔化素材屏幕上的无关原聊天，避免与原创主线矛盾。

音效先依据画面材质选择：液态/磨砂玻璃组件采用玻璃接触声，完整碰撞不配破碎；直接碰撞、边角轻触、擦边与回弹分别按法向/切向速度、重量、位置调增益、尾响与声像。源音频起音经裁切后对齐真实接触，区分时间偏移与声像偏移，不对齐后续共振峰；同一接触跨帧合并，不删除不同对象的同期接触。详细规则见 [可见材质与不同接触方式](sound-design.md#可见材质与不同接触方式)。

检查浅/深/复杂背景、视角极值、按压与展开、前景交叉、转场端点及共同退出。玻璃、模糊、反射、影子和图标随所属组件一起退出，不能留下悬空尾层。重开原生资产，移动目录后核对依赖并重渲有组件的代表帧；解码通过与视觉/听觉通过分别记录。用户否定的版本保留作回退和失败经验，不自动提升为后续质量标准。


### 状态驱动换景与实拍物件释放

控件控制风景时，先让滑动、点按或状态色建立可见因果，再揭示相应新画面。区分“所有初始组件独立出现”和“后续主控件依次聚焦”；素材数量及禁止复用的范围按用户确认登记，不能用不同蒙版重复同一来源来充数。

手机平面挂载的余额或图标释放后，要移交到对应场景运动与接触面，原界面内容同时移除。前景遮挡、真实物体、背景、追踪、合成物体和阴影共用源时间映射；用可见空地安排合理落点，不通过删真实遮挡来露出物体。具体方法与 2.5D 验证边界见 [用户认可的手机控件案例](phone-controls-imagined-vlog.md#追踪物理与遮挡的分工)。

### 弹性释放与容器内液体

- 用户要求更有弹性时，保留释放前原位置，按当前构图由下层向上层错时解除固定；散开由碰撞与回弹发生，不提前重排。调整恢复系数、摩擦、阻尼、质量分布和释放间隔，观察真实求解后的转动与回弹；参数随画面重新验证，不以统一倍速增强物理。
- 亮度/音量的白色填充改作液体时，先保留原图的颜色、填充比例与图标。容器不装满，留出可见自由液面和晃动空间；本次指定纯白，不改成透明水、灰色胶体或整根实心白柱。运动来自容器内液体的重力、惯性、压力/黏性与壁面约束，随倾斜与碰撞改变液面，不用整体移动填充块冒充液体。
- 原生壳体需有内腔、侧壁和前后薄玻璃，组件刚体与内部液体分开建模。可采用经验证的降维粒子求解与网格缓存，但记录二维/三维、单向/双向耦合及表面近似，不能将自定义二维 PBF 说成 Mantaflow。检查全程壁面泄漏、颗粒量、剩余空隙、图标对比度与凹液面的网格；凹轮廓需正确三角剖分，不能用中心扇形错误填白空隙。
- 资产库存放无镜头动作的半满容器、可改参数和来源；镜头粒子轨迹、物理缓存和声音 cue 随工程另存。时间延长后检查旧的出现/退出曲线，避免玻璃仍在但图标提前消失；更新物理后重建接触声音。

- 液体采用三渲二/纯色风格时，分离运动求解与表面着色：保留重力、惯性、壁面约束和自由液面，使用清晰的实色材质，不以磨砂传输、景深、Bloom或alpha羽化模糊液面。容器外壳的磨砂与液体观察窗分开控制；轮廓抖动先在几何上平滑并检查空隙，不能用画面模糊掩盖。以当前参考确定是否使用明暗分区、描边与透明度，本次指定纯白不自动增加灰阶或发光晕。

- 粘稠液体应以邻域黏性、相对运动阻尼和冲击传递限制控制运动，避免碰撞造成瞬间大幅翻涌。检查相邻帧轮廓、显示面积、组件内液体数量与图标明暗；逐帧独立阈值、最大连通区切换和根据覆盖率跳变的图标颜色会制造频闪。可稳定几何距离场并保持面积，再输出清晰实色轮廓；不以交叉淡化或alpha拖影掩盖骤变。对阈值并列值保持确定性，缓存每帧只显示一个液面；检查编码后的连续碰撞片段。用户取消调参界面时只完成修订与验证，不继续制作界面。
